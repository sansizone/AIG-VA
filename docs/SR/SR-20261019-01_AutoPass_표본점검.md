### 3.3 원인 분석

**(1) 같은 콜이 여러 설계에 붙는 구조**
- 녹취 DB `Sponsor_Callinfo.TPANO`에 설계번호가 `;` 구분으로 복수 저장됨
- 수집: `getrealtimeinfo_1` 이 `fn_split_string(TPANO, ';')` 로 분리
- 설계별 콜 매핑: `SttMetaWebAction` → `setsttmetawebaction_3` (`TPANO LIKE '%설계번호%'`, 최근 105일)
- → VA 오류가 아니라 녹취 태깅(TM/녹취 시스템) 단계의 구조

**(2) 점수 상이(73 vs 67) 사유**
- 설계별로 분석 콜 묶음이 다름(②는 10/7 콜 포함)
- 설계별로 AiGEN에서 상품·담보(DMBO_CD)·계피구분(CTRA_INSA_CLCD)을 따로 가져와 비교 스크립트가 다름 (`setsttmetawebaction_4`)
- ② VRS 100: 간편보험 자체 청약녹취는 없으나, 상해 청약콜에 상해사망·이륜차 부담보 등 겹치는 안내가 있어 매칭됨(엑셀 이미지5)

**(3) ③ 사실상 미분석(Grade 6) 사유 — 추정, 데이터 확인 필요**
- 화면의 [분석대상]/[비대상]: `GetUcidDuration.java` — 녹취 DB에 해당 설계로 태깅된 콜 중 `ms_stt_meta`에 없는 콜 = 비대상
  - 쿼리: `oba.oba010p1.getUcid.sel`(aig_rec, `TPANO LIKE`, STT_FLAG='Y'), `oba.oba010p1.getMetaUcid.sel`(ms_stt_meta)
- 나중에 들어온 콜 처리: `GetRTinfoWebAction.java`
  ```text
  설계 d의 녹취DB 콜수(getrealtimeinfo_10) ≠ meta 콜수(getrealtimeinfo_11)일 때
   ├ meta 없음 또는 meta REG_DATE = 오늘
   │   ├ ASS_FLAG 없음 → 신규 콜 추가(재분석)
   │   └ ASS·GRD·BAN_S_FLAG 모두 Y → 추가, 아니면 'R'(보류, VA_FLAG=N)
   └ meta REG_DATE ≠ 오늘 → 'B'(보안콜 처리) → 해당 설계 분석에서 영구 제외
  ```
- 추정 흐름: ③ meta 최초 생성 시점에 태깅돼 있던 콜(9/23, 9/28, 10/6 13:16)만 포함 → 이후 10/6 14:18·10/7·10/8 콜이 늦게 태깅되거나 STT가 늦게 끝남 → meta 생성일이 지나 'B' 처리 → 비대상

### 3.4 확인 쿼리 (미실행)

```sql
-- ① VA DB(is_stat): meta 생성 시점
SELECT CON_ENT_DGN_NO, UCID, UCID_DATE, REG_DATE, GRD_FLAG, ASS_FLAG
FROM ms_stt_meta WITH(NOLOCK)
WHERE CON_ENT_DGN_NO IN ('942606798645','942606829152','942606887558')
ORDER BY CON_ENT_DGN_NO, UCID_DATE;

-- ② 녹취 DB(aig_rec): 콜별 태깅·STT 완료·VA 처리 상태
SELECT FILEID, RecStartDT, Duration, TPANO, STT_FLAG, STT_R_TIME, VA_FLAG, InsDate
FROM Sponsor_Callinfo WITH(NOLOCK)
WHERE TPANO LIKE '%942606887558%'
ORDER BY RecStartDT;
```

- 판정: 10/6 14:18, 10/8 09:14 콜의 `VA_FLAG='B'` 이고 STT 완료(InsDate)가 ③ meta `REG_DATE`보다 늦으면 확정
- 보조: 배치 로그 `### CON_ENT_DGN_NO :: 942606887558`

## 4. 문의 2 — 준수문장 "No data available"

### 4.1 호출 구조

- 화면 `webapps/OBA/OBA010T3.xhtml` `getVrsDetailStt()` → `service::msens.xcron.hansol.sttEncryptWebaction.do` (TYPE=D, `_sqlName=oba.oba010t3.getVrsDetailRes2.sel`)
- Action `src/xcron/com/webaction/SttEncryptWebAction.java` `getDecryptStt()`
- callback(207~209행)은 `res.DS_RES`가 있다고 가정하고, CTRA_INSA_CLCD·SC_SCLF_CD로 재필터

### 4.2 원인 후보

1. **(유력) 한 행 복호화 실패 시 전체 미반환** — 루프 전체가 단일 try. 예외 시 `res.param.addValue("DS_RES", …)` 미실행
   - `ENC_FLAG` NULL → NPE (ENC_FLAG는 `ms_stt_rslt_merge` 서브쿼리 — merge 행 없으면 NULL)
   - 복호화 문장 탭 2개 미만 → `split("\t")[2]` AIOOBE
   - ENC_FLAG=Y인데 평문 → 복호화 예외
2. 화면 필터(SC_SCLF_CD/CTRA_INSA_CLCD) 불일치로 0건

### 4.3 운영 소스 재확인(2026-10-20)

- `SttEncryptWebAction.java` 운영 = 로컬 동일
- `getVrsDetailRes2.sel` 운영본은 "20260831 수정" 버전(홍기원 님 SSMS 쿼리와 동일, 244행 정상) → 쿼리 문제 아님. 로컬에 있던 `SNTR_CD` 오타는 운영에 없음
- `OBA010T3.xhtml` callback 구조 동일

### 4.4 확인 방법 (미실행)

- WAS 로그: 화면 조회 시 `#####Sttdecryption Error Message =` 여부
- DB:
  ```sql
  SELECT M.UCID, COUNT(R.UCID) AS MERGE_CNT, MAX(R.ENC_FLAG) AS ENC_FLAG
  FROM (SELECT DISTINCT UCID FROM ms_stt_meta WHERE CON_ENT_DGN_NO IN ('942606812332','942607049746')) M
  LEFT JOIN ms_stt_rslt_merge R ON R.UCID = M.UCID
  GROUP BY M.UCID;
  ```
  MERGE_CNT=0 또는 ENC_FLAG NULL → 원인 확정

### 4.5 개선안 요약 (소스 미수정)

- 대상: `SttEncryptWebAction.java` 1개 (필수)
  - `getDecryptStt()`/`getDecryptMergeStt()` 루프 안 행 단위 try/catch, ENC_FLAG NULL 방어
  - `extractSentence()` 추가(탭 3개 미만이면 원문)
  - `finally`에서 DS_RES 항상 응답
- 선택: 7개 화면 callback 방어(`OBA010T3/T4/T5`, `BIS010P1/020P1/030P1`, `INF100P1`)
- 영향: 공통 Action이라 7개 화면 전부 테스트 필요
- 참고: 클래스 필드(`DS_RES`, `ced_no` 등) 공유에 따른 동시성 위험 — 범위 외
